Breaking: the cms purges cached answers from the Worker's own Workers Cache instead of the zone cache, which never held a Worker's responses. `cloudflareCachePurge()` and its `CMS_CLOUDFLARE_ZONE_ID` / `CMS_CLOUDFLARE_API_TOKEN` settings are gone; put `workersCachePurge(ctx)` in `infra` and set `"cache": { "enabled": true }` in the Wrangler config. A purge also clears a Nuxt site's HTML when it runs in the same Worker and calls the API in-process. A purge refused by the rate limit is retried twice, 12 seconds apart, and Read API answers now carry `s-maxage=3600` (was a day), so a lost purge leaves them stale for an hour at most. On Workers, `cmsNitroHooks` starts every Nuxt answer as `private, no-store, max-age=0`; only a page that read public cms answers, or a host's explicit Cache-Control, is cached (Nuxt's error pages keep Nitro's `no-cache`, which Workers Cache revalidates with the Worker every time). core: `createWorker` passes the invocation's `ctx` to `infra(env, ctx)` (and `scheduled` accepts it), `WorkerContext` gains the optional `cache`, and an answer without its own `Cache-Control` is sent `private, no-store`, so Workers Cache never stores a session's reads.
