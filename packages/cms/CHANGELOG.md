## 0.3.0

### Minor Changes

- a5cebc6: A collection's admin list can be filtered by its reference and select fields. Name them in the collection definition (`filters: ['categories']`); `defineCms` refuses a name that is not a reference or select field of the collection. The Collections screen then shows one filter per named field above the table, labelled with the field's label: a select offers its options, a reference the first 100 items of its collection by title. Choosing a value reloads the list from page 1, with search, sort, paging and the total limited to the matching items; Reset clears it. Collections without `filters` look and behave as before.

  `GET /collections/:collection/items` takes `filter=<field>:<value>`, repeatable (at most 20, all must match): items whose draft field holds the value, a referenced item id or a select option. A field the collection's `filters` does not name answers 400 `CmsInvalid`.

## 0.2.0

### Minor Changes

- 8002758: One language switch per editor instead of a tab strip on every field. While the host has more than one content locale, the page, item, site settings and menu editors show `LocaleSwitch` ("Content language", the language names from `languageName`) above the form, and every localized field, the path, availability and SEO of a page or routed item, and every menu entry's label show the chosen language; the other languages' controls stay mounted and hidden, so nothing typed in them is lost and focus can reach them. The language last chosen holds for every cms editor of the admin until the page reloads, which starts on the first content locale again. Each label shows once (the legend that repeated it is gone). With several content locales a field every language shares says "All languages" next to its label, and a localized control's description names its language for screen readers only (the switch shows it); with one locale there is no switch and neither. The page editor's switch and its preview language are one value: changing either changes both, and a click in the preview turns the editor to the preview's language before focusing the field. A save or publish the server refuses for a value of one language turns the editor to that language, read from the message (`at ["title"]["it"]`, "The it path …", "… is required in en.", "… needs a label in en."). The revision shown under an editor follows its language and has its own switch over the content locales and any other locale its snapshot holds; a language the snapshot lacks shows empty, and one only the snapshot holds is chosen in the revision alone, leaving the editor's language as it was. Stored data, the API and form field names are unchanged.

  Host field widgets now receive `hint`: "All languages" on a field every language shares while there are several content locales, unset otherwise. Declare it (`hint?: string` in `defineProps`) and show it next to the label, as `CmsWidgetProps` documents; a widget that does not declare it, and keeps `inheritAttrs`, gets it as a `hint` attribute on its root element. A localized widget gets no language: the built-in ones read it out through `srHint`.

  `LocaleSwitch` is native radios in a radiogroup named "Content language" (or `label`), underlined like `LocaleTabs`, and renders nothing for fewer than two locales. `FieldProps` takes `srHint`: in the control's description (`aria-describedby`) but not shown, ignored next to `hint`. `FieldToggle` describes its switch by its description, `hint` (now shown at the end of the switch's row, where it was dropped before), `srHint` and help, all outside the switch's label; a form error replaces that description while it shows. `MediaPicker` takes `hint` and `srHint` and is a group named by its label and described by them.

  The rich text editor's editable area takes its accessible name from the field's label and its description (hint, help, error) from the form field, as Nuxt UI's own inputs do: `RichTextControl` takes a `label`.

- 516ae41: The sidebar lists what you can open and keeps your place. A `NavItem` takes `children` (`NavChild`: a message key or a name per admin locale, and route params): the item becomes an expandable group whose entries open its route with their params, drawn as a tree (a line down the side, a rounded branch and a dot into each entry, darker on the current one), and a group opens itself when you are in it and otherwise stays as you left it. cms lists every collection under Collections and every menu under Menus, so their screens lose the row of tab buttons and take the collection's or menu's name as their title. A route's `nav` names the nav entry a screen without one belongs to (`cms.page` → Pages, `cms.item` → Collections, `users.user` → Users, `emails.template` → Email templates), and `useNavTarget()` names the exact entry when the route cannot (an item editor names its collection); the entry stays highlighted and the navbar shows its name on detail screens, where it was empty. Content reads Pages, Collections, Menus, Media, Redirects, Site settings in every host (`order` 10 to 60); a host's own Content item with the default `order` 0 now sorts above Pages, so give it an `order` above 60 to keep it after them. Nav items without a `group` now show next to Dashboard as documented; they were dropped whenever another group existed. The user screen gets a breadcrumb back to Users.

  `Brand` takes `wordmark` (a wide logo that includes the name, shown instead of mark and name in the open sidebar) and `wordmarkDark`, and `logoDark` for the square mark.

- d3f7e8a: Unsaved changes are never missed. `useUnsavedChanges({ current, saved, save, discard, busy?, saveLabel?, bar? })` registers an editor with the shell: while what is on screen differs from what was saved (`sameContent`: empty values a form writes on its own, `null`, `''`, `false`, `[]` and `{}`, do not count), the shell shows `UnsavedChangesBar` under the screen (always in view) with "Unsaved changes", Discard (asks first, then puts the saved values back without a request) and the editor's Save; Cmd/Ctrl+S saves (not behind an open dialog); a polite live region announces the bar; leaving for another path, signing out or reloading asks "Discard unsaved changes?" once (not for a redirect a guard starts, not after the session ended, not while the editor's own save is in flight, which carries its changes); the new-version Reload asks too. `useLeaveGuard(dirty)` adds state that saves on its own (a widget) to the guard without the bar; `confirmDiscard()` asks before an in-screen switch replaces edits.

  The page, item, site settings and menu editors use it: "Save draft" moves from the header to the bar, and the header keeps the status, Publish (saves what is on screen first), Unpublish and Delete. The page editor uses `PublishActions` like the others. Unpublish asks first ("Take it off the website?") and no longer replaces edits on screen with the saved draft. The cache-purge notice sits under the header on every editor.

### Patch Changes

- 5d53e23: Lists keep every column in view and answer the same way on every screen. `DataTable` cells wrap (long words and paths anywhere) instead of Nuxt UI's one line, so a long title or path no longer pushes the columns after it out of the visible box (a collection with long post titles hid Status and Updated on a 1440 px screen); a column with `nowrap: true` stays on one line (statuses, dates, numbers). The first load shows "Loading…" instead of the empty state; a failed load shows its message with a "Try again" button and no empty state (`errorMessage` sets the message; the `error` slot still replaces both); an empty result while a search or filter is active says "Nothing matches the search or filters." with Reset; clickable rows get the pointer cursor.

  `formatDate` and `formatDateTime` (medium date, short time, the admin locale) format every list and history date: pages, items, revisions, media and the email log. The cms column reads "Updated" as media's does. Pages sort by any column like a collection's items; the users list sorts by status; email templates open on a row click like every other list and name their languages; the email log and template columns follow a language switch.

- 8f1f383: Every editor saves and asks the same way. `useCloseGuard({ isOpen, close, dirty })` guards a slideover that holds a small record's form: bound as `v-model:open`, `:dismissible` and `@close:prevent`, it makes Cancel, ×, Escape and an outside click ask "Discard unsaved changes?" while the form has unsaved changes and close at once while it has none, and `leave()` asks the same before another row or a new record replaces the form (one question at a time, so its answer applies to the request that asked). `useUnsavedChanges` takes `within` (the element holding a form inside a dialog: Cmd/Ctrl+S saves while that dialog is open, but not behind another dialog over it, such as a delete confirmation) and `guardWhileBusy` (leaving keeps asking while a save of several requests runs, since leaving would cut it short).

  Roles, invitations and redirects open in a slideover instead of a card above the list: the form in the body, its message at the top (success green, failure red), Cancel and the primary action ("Save", "Send the invitation"; Delete for an existing redirect, whose confirmation now says what deleting does) in the footer. Each form registers with `useUnsavedChanges({ bar: false, within })`, so leaving the screen asks and Cmd/Ctrl+S saves it from inside the slideover; a new role or invitation with nothing typed has no unsaved changes, and a role's permissions compare as a set, so unchecking and checking one again is no change. A saved role, a sent invitation or a saved or deleted redirect closes the slideover and says so above the list; Super admin still only explains that it cannot be edited; Import CSV stays in the header. The media details slideover asks the same before it closes or another item opens while alt text or a caption is unsaved, and an upload asks before it starts; that text survives Replace file, Archive and Restore, Cmd/Ctrl+S saves it, and the fields are locked while a request runs.

  The user screen's roles save from the unsaved-changes bar ("Save roles" is gone), and a language change, a deactivation, a reactivation or a refused save no longer resets unsaved role toggles; the admin language still applies at once; messages are green or red. The email template editor saves from the bar: Save stores every language whose subject or body differs from what emails use (its override, else the default), one after another, with the fields locked meanwhile and leaving asking until the last one is stored; a refused language keeps its changes, shows why and opens its tab while the others save, and Discard puts every language back. The per-language Save button is gone; Preview, Send me a test and Reset to default stay, and a language with unsaved changes notes that the test uses the saved wording. "Send this email" still applies at once and now says whether it was saved (a failure turned it back without a word); Reset to default waits in its dialog until done.

## 0.1.0

### Minor Changes

- a8834b3: Add collections, site settings and menus. `defineCms` now takes `collections` (fields, optional `routed` for items with their own path, availability and SEO per content locale, optional `titleField`), `settings` (host fields added to the built-in global SEO fields `siteName`, `titleTemplate`, `defaultImage`, `twitterHandle`) and `menus` (by key, nesting `depth` 1 to 3). New field kinds: `fields.link` (a page, an item, a system page or a URL, stored as the reference) and `fields.reference({ collection, many })`. Items, the site settings and each menu hold a draft and a published document like pages, with preview, publish/unpublish, a revision per publish and Audit events (`cms.item.*`, `cms.settings.*`, `cms.menu.*`). Routed items share the URL space with pages, so a path change on publish leaves a redirect behind. Publishing purges `cms:item:<id>` + `cms:collection:<key>` (items) and `cms:site` (settings, menus). Admin screens under Content > Collections, Menus and Site settings; permissions `cms.collections.view|edit|publish` and `cms.site.view|edit|publish`. `@opulonjs/cms/server` exports `Items`, `Settings`, `Menus` and `resolveLinks(links, locale)` for the Read API.
- 1279fe7: Add page templates. `defineCms` takes `templates` by key: a `label`, an optional `description` and the `sections` a new page starts with, in order, each with its section `type` and optional `data` in the stored shape (localized fields hold `{ [locale]: value }`). `defineCms` throws when a template would make `pages.create` fail: an unknown section type, data that does not decode against the type's fields (unknown fields included), more than 200 sections, or a link that a page refuses (a URL that is not http(s), `mailto:`, `tel:`, a site path or a fragment, an unknown system page, or a page or item id that is not a uuid). TypeScript also rejects an unknown section type. When the host defines templates, Content > Pages "New page" opens a picker with "Blank page" and every template, and the new page starts with the chosen template's sections. Without templates, "New page" creates a blank page in one click as before. Media ids are per database, so a template can only prefill an image whose id the host seeds.
- 2115e60: Add `@opulonjs/cms` pages. A host declares section types and system pages once with `defineCms({ sections, systemPages })` and the `fields` builders (`text`, `textarea`, `richText`, `number`, `select`, `boolean`, `media`, `custom`: an Effect Schema per value plus admin metadata; text kinds are localized per content locale) from `@opulonjs/cms/api`, and passes the same file to `cms({ definitions })` (`@opulonjs/cms/server`) and `cmsAdmin({ definitions, widgets })` (`@opulonjs/cms/admin`). cms ships the `rich_text` section type, sanitized server-side against a restricted allowlist. Pages hold a draft and a published JSON document with a path, availability and SEO per content locale; the server validates drafts against the definitions, keeps paths unique per locale, and on publish checks required fields, records a revision, writes the `cms.page.published` Audit event with its `revisionId` and purges the page's Cache-Tag after commit (`CachePurge`, a no-op until the host provides one). Unpublish and delete are audited too; system pages cannot be deleted. Preview (`GET /api/cms/pages/:id/preview?locale=`) returns the draft in one locale, permission-checked and `private, no-store`. Permissions: `cms.pages.view`, `cms.pages.edit`, `cms.pages.publish`. `cmsAdmin` adds Content > Pages with forms generated from the definitions (locale tabs, `MediaPicker` for media fields) and fails at composition when a field names an unregistered widget. Requires `vue-router` as a peer (the admin shell's router).
- 9acc196: Add the cms Read API, public and unauthenticated under `/api/cms`: `resolve?path=` answers a page, item, redirect or not-found union per public path (default content locale unprefixed, others prefixed with the locale), `site?locale=` the published settings, menus with resolved hrefs and the system pages map, `collections/:key` published items with paging, sort, `ref` and `ids` filters, and `sitemap.xml` with one `/api/cms/sitemaps/<key>.xml` child per `sitemapSource` contribution (cms contributes `cms.pages` and `cms.items.<collection>` for routed collections). Media ids resolve to `ResolvedMedia` (now a schema in `@opulonjs/media/api`) and link fields to hrefs. Answers carry `Cache-Control` and `Cache-Tag`; publish, unpublish, delete and redirect writes purge the tags after commit, and `workersCachePurge(ctx)` purges them from the Worker's own Workers Cache. `resolveLinks` now returns `{ href, tags }` with public paths, and a default-locale path may no longer start with another locale's prefix.
- 18247cd: Add cms redirects: exact-path rules per content locale (`from` → `to`, 301 or 302, trailing slash ignored). Publishing a page whose path changed redirects the old path to the new one in the same transaction, and drops redirects from paths the page now answers at. The set stays flat: a redirect onto a redirected path points at its final target, and loops, repeated `from` paths and `from` paths of published pages are refused (409). Editors manage redirects under Content > Redirects and import a CSV file with a `from,to[,status][,locale]` header (at most 5,000 rows, 1 MB), getting created / skipped / per-row errors back. Every write is an Audit event (`cms.redirect.created`, `updated`, `deleted`, `imported`). Permissions: `cms.redirects.view`, `cms.redirects.edit`. `Redirects.lookup(locale, path)` from `@opulonjs/cms/server` returns the redirect for a request path, for the Read API.
- 0e12f3b: Add revision history, snapshot views, and audited draft restore for pages, collection items, site settings, and menus. Restoring requires the document's publish permission; publishing remains a separate action.
- b1d7be7: Add `@opulonjs/cms/site` for a host's public site, without Effect in its bundle: `createCmsClient({ fetch, baseUrl })` reads `resolve`, `site`, `collection` and the editor-only `previewPage`/`previewItem` as the Read API's JSON types; `buildHead` builds the `useHead` input (title template, description, OG with the default image fallback, noindex, absolute canonical, hreflang and `x-default`); `systemPageLink`, `menu` and `localeLinks` cover links and the locale switcher; `<CmsSections>` renders sections from a `sectionComponents<typeof definitions>({...})` map that must cover every section type, with `CmsRichText` for `rich_text`. Add `@opulonjs/cms/site/nuxt`: `cmsNitroHooks(worker)` gives SSR on Workers an in-process cms fetch and copies the Read API's Cache-Tags onto the HTML (`?preview` forwards the editor's cookie and answers `private, no-store`), and `useCmsClient()` picks that fetch during SSR and the real one in the browser. `nuxt` is an optional peer.
- 16f34ba: Page, sort and search users and collection items on the server. Reference fields use the shared searchable table, retain selected items across pages, and discard stale loads; saved references that were deleted or are not item IDs show as missing and stay removable. Item links pick a collection, then search its items, instead of listing every item in one select; removing the target clears the link. Users list responses now include a total and both list endpoints default to 25 rows with a 100-row maximum and bounded offsets. Both lists take `page`, `perPage`, `search`, `sort` and `direction`; the items list also takes `ids` (up to 100 comma-separated item IDs) and the users list `id` (one user).

  Breaking changes for API consumers:

  - `GET /cms/collections/{collection}/items` and `GET /users/users` (under the host's API prefix, `/api` by default) now return one page, 25 rows by default, instead of every row. Request further pages (`page`, `perPage` up to 100) to read them all.
  - The server services `Items.list(collection, query)` (`@opulonjs/cms/server`) and `UserManagement.users(query)` (`@opulonjs/users/server`) now take a required `query` and return one page with its `total`. Calls without a query, such as `Items.list('posts')`, no longer type-check and fail at runtime.

- fbd8cac: Purge cached Read API answers after media metadata edits, replacements, archive, and restore. Answers include media dependency tags, with a broad media fallback for oversized headers.

  Core now owns a durable cache purge outbox with three attempts, a bounded scheduled sweep, and a 20-second attempt deadline. CMS and media editors see pending and exhausted failures until cached answers expire. Move host imports of `workersCachePurge` to `@opulonjs/core/workers` and custom purge layers from CMS `CachePurge` to core `CachePurger`; adapters must fail on errors or refusals.

  Core exposes sanitized purge status at `GET /api/cache-purges` for permissions declared by producer modules through `cachePurgeStatusAccess`. The CMS status route is removed. Admin exports `CachePurgeNotice`, shared by CMS and media screens.

- 5f8d9d9: Two editors on the same page, item, site settings or menu no longer overwrite each other's draft. Every document now carries a `version` that every draft write (save, publish, revision restore) advances. Saving, publishing or restoring a revision names the version the editor loaded; when the draft changed meanwhile, the request answers 409 `CmsConflict` with reason `draft_changed` and changes nothing. The admin keeps the editor's unsaved input on screen, says the draft changed, and offers to reload it. While a save, publish or restore is in flight the editor form is locked (fields, rich text and reference pickers), so nothing typed can be replaced by the response. Once the request ends, focus returns to the control that had it, or to the form itself when that control is gone or hidden. `RichTextControl` now follows its `disabled` prop after mount and announces it as `aria-disabled`.

  Breaking changes for API consumers:

  - `PUT /cms/pages/{id}/draft`, `POST /cms/pages/{id}/publish`, `PUT /cms/items/{id}/draft`, `POST /cms/items/{id}/publish`, `PUT /cms/settings/draft`, `POST /cms/settings/publish`, `PUT /cms/menus/{key}/draft`, `POST /cms/menus/{key}/publish` and the four `POST .../revisions/{revisionId}/restore` endpoints (under the host's API prefix, `/api` by default) require a `version` query parameter: the `version` of the document as last read. Without it they answer 400. Read the document first, or use the document the previous save, publish or restore returned.
  - `Page`, `PageSummary`, `Item`, `ItemSummary`, `SiteSettings`, `Menu` and `MenuSummary` have a new `version` field.
  - The server services `Pages.saveDraft(id, version, draft)`, `Pages.publish(id, version)`, `Items.saveDraft(id, version, draft)`, `Items.publish(id, version)`, `Settings.saveDraft(version, draft)`, `Settings.publish(version)`, `Menus.saveDraft(key, version, draft)`, `Menus.publish(key, version)` and every `restoreRevision(..., revisionId, version)` (`@opulonjs/cms/server`) take the loaded version. `Settings` and `Menus` saves, publishes and restores can now fail with `CmsConflict`.
  - Migration `0005_document_version` adds `cms.document.version`; run `opulon migrate` before deploying.

- b19c299: Edit pages in three panes: the page settings and the ordered section list on the left (select, add, move, remove), a live preview of the unsaved draft in the middle, and the inputs of the selected section or the page settings on the right. The layout follows the editor's own width: three panes when they fit, the preview beside the outline and inputs on medium widths (a 1024 px screen with the sidebar), one stacked column on narrow screens. Pass `cmsAdmin({ preview: { url } })` to show the host site's page in the preview frame; without it the editor has two panes. Clicking a section in the preview selects it and focuses its input (the input of the field a `data-cms-field` element names) in the language the preview shows. `@opulonjs/cms/site` exports `useCmsLivePreview(initial, { adminOrigin })`, which renders the draft the admin posts for the same page and reports clicks; it accepts messages only from `adminOrigin`, only inside a frame on a `?preview` page, and does nothing without an origin; section markers and click handling start once the admin posts a draft of the page shown; when the URL loses `?preview` or a reactive `adminOrigin` goes away, it drops the draft and stops. In live mode `CmsSections` marks each section root with `data-cms-section`. The admin builds the preview with the same code as `GET /pages/:id/preview` from the draft cleaned as Save cleans it (rich text sanitized, URL links and SEO text trimmed, empty values dropped, URL links Save would refuse left out); nothing is saved until Save or Publish.

  `LocaleTabs` takes an optional `v-model` with the locale whose tab is shown.

- fe35a6d: First public release: the seven packages ship together as 0.1.0, proven by the fixture host on real Workers with Hyperdrive, R2 and the cron trigger.
- 2130809: Breaking: the cms purges cached answers from the Worker's own Workers Cache instead of the zone cache, which never held a Worker's responses. `cloudflareCachePurge()` and its `CMS_CLOUDFLARE_ZONE_ID` / `CMS_CLOUDFLARE_API_TOKEN` settings are gone; put `workersCachePurge(ctx)` in `infra` and set `"cache": { "enabled": true }` in the Wrangler config. A purge also clears a Nuxt site's HTML when it runs in the same Worker and calls the API in-process. A purge refused by the rate limit is retried twice, 12 seconds apart, and Read API answers now carry `s-maxage=3600` (was a day), so a lost purge leaves them stale for an hour at most. On Workers, a Nuxt page is cached publicly only when it calls the new `useCmsPublicPage()` during its render and every cms read was public; every other answer without a Cache-Control, however it was sent, gets `private, no-store` from the new `cmsNitroPlugin(worker)` (`export default defineNitroPlugin(cmsNitroPlugin(worker))`, which replaces wiring `cmsNitroHooks` by hand and throws at setup on a Nitro without `localFetch`), and a host's Cache-Control is never replaced. core: `createWorker` passes the invocation's `ctx` to `infra(env, ctx)` (and `scheduled` accepts it), `WorkerContext` gains the optional `cache`, and an answer without its own `Cache-Control` is sent `private, no-store`, so Workers Cache never stores a session's reads.
