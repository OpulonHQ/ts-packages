Add `@opulonjs/cms` pages. A host declares section types and system pages once with `defineCms({ sections, systemPages })` and the `fields` builders (`text`, `textarea`, `richText`, `number`, `select`, `boolean`, `media`, `custom`: an Effect Schema per value plus admin metadata; text kinds are localized per content locale) from `@opulonjs/cms/api`, and passes the same file to `cms({ definitions })` (`@opulonjs/cms/server`) and `cmsAdmin({ definitions, widgets })` (`@opulonjs/cms/admin`). cms ships the `rich_text` section type, sanitized server-side against a restricted allowlist. Pages hold a draft and a published JSON document with a path, availability and SEO per content locale; the server validates drafts against the definitions, keeps paths unique per locale, and on publish checks required fields, records a revision, writes the `cms.page.published` Audit event with its `revisionId` and purges the page's Cache-Tag after commit (`CachePurge`, a no-op until the host provides one). Unpublish and delete are audited too; system pages cannot be deleted. Preview (`GET /api/cms/pages/:id/preview?locale=`) returns the draft in one locale, permission-checked and `private, no-store`. Permissions: `cms.pages.view`, `cms.pages.edit`, `cms.pages.publish`. `cmsAdmin` adds Content > Pages with forms generated from the definitions (locale tabs, `MediaPicker` for media fields) and fails at composition when a field names an unregistered widget. Requires `vue-router` as a peer (the admin shell's router).
