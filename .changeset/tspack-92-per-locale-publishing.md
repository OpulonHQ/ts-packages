Editors publish a page or collection item in only some content locales. The page editor (page settings) and the item editor show one Languages control, a checkbox per content locale, for routed and unrouted collections alike; it replaces the per-locale "Available in this language" switch. A host with one content locale gets a single "Available on the website" checkbox. A routed document still needs a path in each locale it is available in.

Unrouted items are now available per locale too. A locale an unrouted item's write does not name is available, so `POST /collections/:collection/items` with `locales: {}` makes it available everywhere, as before. The Read API's `GET /collections/:collection?locale=` lists an unrouted item only in the locales its published document is available in; routed items keep the published-path rule. Migration `0006_unrouted_items_available` marks every stored locale of the host's unrouted collections' items available, in draft, published and revisions alike, so their status does not change and a restored revision stays listed.

`PageSummary` and `ItemSummary` gain `locales`: the content locales the draft is available in, in content-locale order. A row's `title` and `path` come from its list locale: the default locale when the draft is available there, else its first available locale. `path` is the public path in that locale (`/it/contatti`), so an Italian-only page lists with its Italian title instead of "Untitled". Search and sort in `GET /collections/:collection/items` use these values. The Pages and collection lists show a Languages column with a chip per available locale and a Language filter (hosts with several content locales). `GET /collections/:collection/items` takes `availableIn=<locale>`: items whose draft is available there; a value that is not a content locale answers 400 `CmsInvalid`.

Publishing checks required localized fields in each locale the document is available in (the default locale when it is available in none); a value in the default locale fills any of them, as the Read API falls back to it. A document available in the default locale is checked as before. Site settings keep the default-locale check.
