# @opulonjs/core

## 0.1.0

### Minor Changes

- 75a1754: Add the admin skeleton: `defineAdminModule`, `createAdmin` (hides modules missing from `/me`, reload notice on a new build), `useApiClient` for a module's own HttpApi group, and the `opulonAdmin()` Vite preset in `@opulonjs/admin/vite` (build id and API prefix injection). Core adds a minimal `/me` (build id, enabled module ids; `createWorker` now takes `buildId`), `serveAdmin` in `@opulonjs/core/workers` for the `/admin` SPA fallback and immutable assets, and the client-safe `@opulonjs/core/api` entry for module `/api` files.
- 6636323: Add a permission-protected audit API, a filterable admin audit log, and reusable subject timelines on user detail screens.

  IP addresses and user agents are masked when events are past the configured IP retention window, even before the retention task runs. Audit paging is capped at offset 10,000; the admin shows the accessible history window and suggests refining filters.

  Breaking for hosts using module IDs `me` or `audit`: composition now rejects these IDs because core owns their root API routes. Rename those host modules before upgrading.

  DataTable adds the optional `maxPage` prop and `error` and `pagination-limit` slots for bounded paging and custom failure and limit messages.

- 7a40f65: Add the rest of core: the `core()` module (hosts list it), `Audit.record` and `diffFields` writing `core.audit_event` in the caller's transaction, the daily `core.audit_purge` retention task (365 days, IP/UA nulled after 90, configurable via `core({ audit })`), `requirePermission` with an anonymous-by-default `CurrentActor` (the Authorization middleware sets the signed-in user, tasks run as the system actor), Effect `Config` read from the Worker env's string values only, and a staff-only `/me` (`private, no-store`) returning the user, admin locale, permission keys, enabled module ids, the permission catalog and the build id. `CurrentUser` now carries `name`, `email` and `locale`; `systemActor` is now a function taking the actor name. The admin's `Me` type follows the richer `/me`.
- 989b8f8: Add `@opulonjs/emails`: modules declare email templates with `emailTemplate({ key, audience, placeholders, defaults })` in `contributes` (they must depend on `emails`), and send them with `EmailService.send(template, { to, locale, vars, about })`. A send writes a queued email log row in the caller's transaction and is delivered after commit; the `emails.outbox_sweep` task retries (3 attempts with backoff) and `emails.log_purge` removes rows after 90 days. Staff emails render in the recipient's admin locale, public ones in a content locale. The host configures `emails({ from, brand, layout?, adminLocales?, contentLocales? })` and provides a `Mailer` in its infra: `Mailer.resend()` (secret `EMAILS_RESEND_KEY`), `Mailer.log` or `captureMailer()` for tests. `emailsAdmin()` adds the email log screen (`emails.log.view`); pass the package's directory in `opulonAdmin({ sources })`. Core adds `defineExtensionPoint` and `contributes` on `defineModule`: composition rejects duplicate contribution keys, a missing owner, a contributor without `dependsOn` on the owner and keys outside the contributor's prefix.
- 6a1cb67: Add the media library on R2. `media({ maxBytes, widths, imageUrl })` from `@opulonjs/media/server` serves `/api/media`: multipart upload through the Worker into `MediaStorage` (`R2MediaStorage(env.MEDIA_BUCKET)` from the host's infra), a magic-byte allowlist (JPEG, PNG, WebP, AVIF, GIF, PDF; no SVG or video) and a 20 MB default limit, rejected uploads answering `MediaRejected` with a readable message, image dimensions, alt text and captions per content locale, replace (same id, new version and URL, old URL keeps serving), archive and restore (no delete), permissions `media.view`, `media.upload`, `media.archive`, and Audit events for every write. `serveMedia(request, storage)` answers `/media/<id>/<version>/<filename>` with immutable caching; `ImageUrl` builds `/cdn-cgi/image` URLs and `MediaLibrary.resolve(ids, locale)` gives `{ url, alt, caption, width, height, mime, srcset }` for rendering. `@opulonjs/media/admin` adds `mediaAdmin()` (Content > Media) and `MediaPicker`. Core: hosts declare content locales once with `composeServer({ contentLocales })`; modules read them through `ContentLocales`, and `/me` (and the admin's `Me`) now include `contentLocales`.
- 358c403: Add the module contract and server skeleton: `defineModule`, `composeServer` (startup checks and the unprovided-services type check), `createWorker` and `PgFromHyperdrive` in `@opulonjs/core/workers`, and the `opulon migrate` CLI.
- 16f34ba: Page, sort and search users and collection items on the server. Reference fields use the shared searchable table, retain selected items across pages, and discard stale loads; saved references that were deleted or are not item IDs show as missing and stay removable. Item links pick a collection, then search its items, instead of listing every item in one select; removing the target clears the link. Users list responses now include a total and both list endpoints default to 25 rows with a 100-row maximum and bounded offsets. Both lists take `page`, `perPage`, `search`, `sort` and `direction`; the items list also takes `ids` (up to 100 comma-separated item IDs) and the users list `id` (one user).

  Breaking changes for API consumers:

  - `GET /cms/collections/{collection}/items` and `GET /users/users` (under the host's API prefix, `/api` by default) now return one page, 25 rows by default, instead of every row. Request further pages (`page`, `perPage` up to 100) to read them all.
  - The server services `Items.list(collection, query)` (`@opulonjs/cms/server`) and `UserManagement.users(query)` (`@opulonjs/users/server`) now take a required `query` and return one page with its `total`. Calls without a query, such as `Items.list('posts')`, no longer type-check and fail at runtime.

- fbd8cac: Purge cached Read API answers after media metadata edits, replacements, archive, and restore. Answers include media dependency tags, with a broad media fallback for oversized headers.

  Core now owns a durable cache purge outbox with three attempts, a bounded scheduled sweep, and a 20-second attempt deadline. CMS and media editors see pending and exhausted failures until cached answers expire. Move host imports of `workersCachePurge` to `@opulonjs/core/workers` and custom purge layers from CMS `CachePurge` to core `CachePurger`; adapters must fail on errors or refusals.

  Core exposes sanitized purge status at `GET /api/cache-purges` for permissions declared by producer modules through `cachePurgeStatusAccess`. The CMS status route is removed. Admin exports `CachePurgeNotice`, shared by CMS and media screens.

- 0832d55: Add `withTransaction` (nested calls use savepoints), `Background.afterCommit`, scheduled tasks (`tasks: [{ name, every: '5m' | '1h' | '1d', run }]` on `defineModule`, run as the system actor from one `*/5` cron through `createWorker().scheduled`) and `CurrentActor`/`systemActor`. `createWorker` disposes each invocation's runtime only after its background work settled.
- 5553449: Add `@opulonjs/users`: staff sign-in with email and password through Better Auth (login and sessions only, PBKDF2 hashes, its own `pg` pool over the SqlClient's URL, session cookie cache off, same-origin `httpOnly`/`SameSite=Lax` cookies, rate limits per client address in the database), invite-only onboarding (`POST /api/users/invitations`, `users.manage`; the invitee sets a password through the emailed link), password reset by email, deactivated users refused, and `users.*` audit events for sign-in, failed sign-in, sign-out, invitations and resets. `users()` implements core's Authorization middleware from the session (permissions from the user's roles; the built-in Super admin holds every composed permission) and reads Config `USERS_BASE_URL` and `USERS_AUTH_SECRET`. `usersAdmin()` is the admin's auth provider with the sign-in, forgotten password, reset and invitation screens. `opulon users invite-super-admin --server <file> --email <address>` prints the first Super admin's invitation link. Core adds module `commands` for the `opulon` CLI (`opulon <module id> <command>`) and exports `Composed`; the admin shell gets a sign-out button (`AuthProvider.signOut`), `useAdmin().refresh()` and re-exports `useRoute`/`useRouter`.
- fe35a6d: First public release: the seven packages ship together as 0.1.0, proven by the fixture host on real Workers with Hyperdrive, R2 and the cron trigger.
- 2130809: Breaking: the cms purges cached answers from the Worker's own Workers Cache instead of the zone cache, which never held a Worker's responses. `cloudflareCachePurge()` and its `CMS_CLOUDFLARE_ZONE_ID` / `CMS_CLOUDFLARE_API_TOKEN` settings are gone; put `workersCachePurge(ctx)` in `infra` and set `"cache": { "enabled": true }` in the Wrangler config. A purge also clears a Nuxt site's HTML when it runs in the same Worker and calls the API in-process. A purge refused by the rate limit is retried twice, 12 seconds apart, and Read API answers now carry `s-maxage=3600` (was a day), so a lost purge leaves them stale for an hour at most. On Workers, a Nuxt page is cached publicly only when it calls the new `useCmsPublicPage()` during its render and every cms read was public; every other answer without a Cache-Control, however it was sent, gets `private, no-store` from the new `cmsNitroPlugin(worker)` (`export default defineNitroPlugin(cmsNitroPlugin(worker))`, which replaces wiring `cmsNitroHooks` by hand and throws at setup on a Nitro without `localFetch`), and a host's Cache-Control is never replaced. core: `createWorker` passes the invocation's `ctx` to `infra(env, ctx)` (and `scheduled` accepts it), `WorkerContext` gains the optional `cache`, and an answer without its own `Cache-Control` is sent `private, no-store`, so Workers Cache never stores a session's reads.

### Patch Changes

- 2cfa7cb: `serveAdmin` answers a missing hashed `/admin/assets/*` file with `no-store`, so a request that races a deploy (new `index.html`, assets not yet everywhere) is not kept as a 404 by Workers Cache or the CDN.
- d469616: Better Auth no longer prints its log messages or failing errors whole: an unexpected error fails the request and the Worker logs its names and codes (a Postgres error's SQLSTATE included), and Better Auth's other log lines reach the Effect log with their messages dropped. `describeError` (core) is the redaction both use.

  Sign-in refuses a request whose `Origin` is another site (login CSRF), and a session revoked while Better Auth refreshes it answers as signed out instead of a 500.

- e134aff: Fixes from the redeploy smoke. A revalidated admin file (304) is no longer answered with `index.html`, which broke the logo after the first load. A request that ends in a 5xx logs its cause; Better Auth server errors carry their response body. A rate-limited sign-in reports a `retryAfter` within the window: Better Auth's pool now reads `bigint` as a number. The default admin theme follows Kumiba: neutral grays, a black primary in light mode and a white one in dark mode, unless the brand sets its own.
- 82541fe: Review fixes. users: a session is created atomically with deactivation and password reset (migration 0002), invitations are checked and written under the users/roles lock, one pending invitation per address (migration 0003), and accepting an invitation is rate limited per address and checks the token before hashing the password. cms: redirect paths are decoded and canonical (dot segments, repeated slashes) for writes, CSV import and lookup; backslashes and `//` are refused. emails: the retry cap holds when a last attempt was cut off; public emails use core's content locales (the `contentLocales` option is removed); bodies are sanitized with sanitize-html instead of xss. core: composition refuses the Authorization middleware or a Policy on a public group.
- 0fd36d5: Reject audit Through dates after 9999-12-30 with localized validation and share the default audit page size. Trim exact-match audit filters and ignore whitespace-only values.
