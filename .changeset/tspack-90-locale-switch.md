One language switch per editor instead of a tab strip on every field. While the host has more than one content locale, the page, item, site settings and menu editors show `LocaleSwitch` ("Content language", the language names from `languageName`) above the form, and every localized field, the path, availability and SEO of a page or routed item, and every menu entry's label show the chosen language; the other languages' controls stay mounted and hidden, so nothing typed in them is lost and focus can reach them. The language last chosen holds for every cms editor of the admin until the page reloads, which starts on the first content locale again. Each label shows once (the legend that repeated it is gone). With several content locales a field every language shares says "All languages" next to its label, and a localized control's description names its language for screen readers only (the switch shows it); with one locale there is no switch and neither. The page editor's switch and its preview language are one value: changing either changes both, and a click in the preview turns the editor to the preview's language before focusing the field. A save or publish the server refuses for a value of one language turns the editor to that language, read from the message (`at ["title"]["it"]`, "The it path …", "… is required in en.", "… needs a label in en."). The revision shown under an editor follows its language and has its own switch over the content locales and any other locale its snapshot holds; a language the snapshot lacks shows empty, and one only the snapshot holds is chosen in the revision alone, leaving the editor's language as it was. Stored data, the API and form field names are unchanged.

Host field widgets now receive `hint`: "All languages" on a field every language shares while there are several content locales, unset otherwise. Declare it (`hint?: string` in `defineProps`) and show it next to the label, as `CmsWidgetProps` documents; a widget that does not declare it, and keeps `inheritAttrs`, gets it as a `hint` attribute on its root element. A localized widget gets no language: the built-in ones read it out through `srHint`.

`LocaleSwitch` is native radios in a radiogroup named "Content language" (or `label`), underlined like `LocaleTabs`, and renders nothing for fewer than two locales. `FieldProps` takes `srHint`: in the control's description (`aria-describedby`) but not shown, ignored next to `hint`. `FieldToggle` describes its switch by its description, `hint` (now shown at the end of the switch's row, where it was dropped before), `srHint` and help, all outside the switch's label; a form error replaces that description while it shows. `MediaPicker` takes `hint` and `srHint` and is a group named by its label and described by them.

The rich text editor's editable area takes its accessible name from the field's label and its description (hint, help, error) from the form field, as Nuxt UI's own inputs do: `RichTextControl` takes a `label`.
